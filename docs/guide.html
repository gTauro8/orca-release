Release recipes for every project

A short command for push, pull request, deploy and local services. The agent reads the recipe of the project you are in, shows you the checklist and asks for confirmation before anything that can't be undone. They are Orca skills: they work with Claude, Codex and the other agents Orca launches.

The problem it solves

With many different projects (Flutter apps, NestJS APIs with Docker, Go services, static sites, iOS apps) and several git servers, every project has its own commands and steps. It's easy to forget one, or to use another project's command. Here each project is described once, in a recipe, and the skills are the same for all of them.

A recipe

One Markdown file per project. At the top it says how to recognize the repo; below, the steps of each activity.

match:
  remotes: ["git.example.org/team/example-api"]
host: gitea
base_branch: main
---
## push
- [ ] `npm run lint`
- [ ] `npm test`
- [ ] if the Prisma schema changed: the migration exists
## deploy
### dev (confirm)
- [ ] run the release.yml workflow from the Actions page
- [ ] `npm test` <!-- inferred: confirm -->
## compose
- file: `docker-compose.yml`
- project: example-api
- services: postgres payments-mock
- note: Postgres on 5433
autoOne backticked command: the agent runs it, exactly as written.
manualFree text: you do it, the agent waits for your OK.
to confirmA step guessed from the repo: flagged until you confirm it.

What happens when you run a skill

  1. Recognizes the project

    From the git remote or the folder, even inside an Orca worktree.

  2. Shows the checklist

    Every step, marked auto or manual, before doing anything.

  3. Runs in order

    If a step fails it stops: fix it, skip it with a reason, or abort.

  4. Asks for confirmation

    Before push, PR, deploy or deleting data. Never automatically.

  5. Sums up

    What was done, what was skipped and why, links to the PR or release.

The commands

CommandYou can sayWhat it does
/push"push this branch"Checks the branch, runs the project's checks, pushes the branch after confirmation.
/pr"open a PR"Pushes if needed, writes title and description from the commits, opens the PR on GitHub or the right page on Gitea.
/deploy"deploy to staging"Pick the environment or store; runs the steps and asks for confirmation for every step that releases.
/compose"start the services"Starts, stops, shows the status or logs of the local services (db, mocks). Reset deletes data only after a yes.
/dev"start dev"Local services first, then each dev process of the project in its own Orca terminal.
/status"project status"Every project at a glance: uncommitted work, unpushed commits, worktrees, recipes to fix, open PRs.
/align"align the recipes"Compares each recipe with its repo: broken commands, new scripts or workflows, steps to confirm. Proposes the fixes.
/updates"any updates?"Outdated dependencies per project, plus news, breaking changes and security advisories on the technologies you use or want to try. Upgrades nothing.
/prompt"new task: …"Turns a rough request into a structured prompt from the project's real context, then starts it in a new worktree.

Without having to remember

One line with the project's stack and the useful skills. If the recipe no longer matches the repo, it tells you.

Buttons in the Quick Commands menu: they open the agent with the right command, or start the project's services in one click.

How it is built

flowchart LR
  S[Agent session in Orca] --> H[Session-start hint]
  S --> K["/push /pr /deploy /compose /dev"]
  K --> P[Common procedure]
  P --> F[Find recipe]
  F --> R[(recipes/project.md)]
  P --> C{Confirm?}
  C -->|yes| A[Run]
  W["/align + Monday report"] --> SC[Scanner] --> R

The skills are generic and contain no project commands. The scripts that recognize the repo, generate the docker commands and compare the recipes are tested automatically.

Getting started

For you or a colleague

Install in Orca the skill bundle you received as a link, then in a session write "set up the release skills": the agent interviews you about your projects and habits and prepares your recipes in a folder of yours. About 15 minutes, no push or deploy during setup.

To rebuild everything

Give REPRODUCE.md to an agent: it holds the architecture, the contracts, the build order and the pitfalls already found.

Rules that never change

  • The agent only runs commands written in the recipe.
  • Push, PR, deploy and deleting data always need an explicit yes.
  • Recipes live in your own data folder, not in the project repos.
  • Server compose files are never used locally.
  • Reports and updates only read: they upgrade neither dependencies nor projects.
